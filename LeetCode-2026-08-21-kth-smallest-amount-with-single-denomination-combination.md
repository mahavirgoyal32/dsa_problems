### 📝 Problem Description

You are given an integer array coins representing coins of different denominations and an integer k.

You have an infinite number of coins of each denomination. However, you are not allowed to combine coins of different denominations.

Return the kth smallest amount that can be made using these coins.

 
Example 1:


Input: coins = [3,6,9], k = 3

Output:  9

Explanation: The given coins can make the following amounts:
Coin 3 produces multiples of 3: 3, 6, 9, 12, 15, etc.
Coin 6 produces multiples of 6: 6, 12, 18, 24, etc.
Coin 9 produces multiples of 9: 9, 18, 27, 36, etc.
All of the coins combined produce: 3, 6, 9, 12, 15, etc.


Example 2:


Input: coins = [5,2], k = 7

Output: 12 

Explanation: The given coins can make the following amounts:
Coin 5 produces multiples of 5: 5, 10, 15, 20, etc.
Coin 2 produces multiples of 2: 2, 4, 6, 8, 10, 12, etc.
All of the coins combined produce: 2, 4, 5, 6, 8, 10, 12, 14, 15, etc.


 
Constraints:


	1 <= coins.length <= 15
	1 <= coins[i] <= 25
	1 <= k <= 2 * 109
	coins contains pairwise distinct integers.

## AI Generated Solution

To solve the problem "Kth Smallest Amount With Single Denomination Combination", let's first break down the requirements and then create a C++ solution.

### Problem Breakdown

We are given:
- An integer array of distinct denominations `denominations`.
- An integer `k`, which signifies the k-th amount we want to find.

The task is to determine the k-th smallest sum that can be formed using the given denominations, using each denomination an arbitrary number of times.

### Key Insights

1. **Infinite Combinations**: Since we can use any denomination any number of times, the problem translates to finding the smallest sums generated by combinations of these denominations.
  
2. **Stream of Sums**: This problem can be visualized as generating an infinite list of sums using a min-heap (priority queue) to always keep track of the smallest sums generated so far.
  
3. **Min-Heap**: By starting with 0 in the heap and progressively adding the denominations to the smallest sums encountered, we can ensure we are building from the simplest to the more complex sums.

### Approach

1. **Min-Heap Initialization**: Start the min-heap with 0 since 0 is the smallest achievable sum.
2. **Use of Set**: To avoid duplicates (which can occur because of the infinite use of denominations), use a set to track the sums that have already been pushed into the heap.
3. **Iterative Extraction**:
   - Extract the smallest amount from the heap.
   - For each denomination, add it to the extracted amount and push it into the heap if it hasn’t been seen before.
   - Repeat this until we extract the k-th smallest amount.

### C++ Implementation

Here is the C++ code implementing the above logic:
```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <unordered_set>
using namespace std;

int kthSmallestAmount(vector<int>& denominations, int k) {
    // Min-heap to store the smallest amounts
    priority_queue<long long, vector<long long>, greater<long long>> minHeap;
    // Set to track seen amounts to avoid duplicates
    unordered_set<long long> seen;

    // Initialize the min-heap with the first amount 0
    minHeap.push(0);
    seen.insert(0);

    long long amount = 0;

    // Pop from the heap k times to get the k-th smallest amount
    for (int i = 0; i < k; i++) {
        amount = minHeap.top(); // Get the smallest amount
        minHeap.pop(); // Remove it from the heap
        
        // Generate new amounts by adding each denomination
        for (int den : denominations) {
            long long newAmount = amount + den;
            // Only add newAmount if it hasn't been seen yet
            if (seen.find(newAmount) == seen.end()) {
                seen.insert(newAmount);
                minHeap.push(newAmount);
            }
        }
    }

    // The k-th element when loop exits
    return amount;
}
```

### Complexity Analysis

- **Time Complexity**: The loop runs `k` times, and in the inner loop, we potentially examine each of the denominations. Each insert operation into the heap is \(O(\log N)\), where \(N\) is the size of the heap. Therefore, the time complexity can be approximated as \(O(k \cdot m \cdot \log N)\) where \(m\) is the number of denominations.
  
- **Space Complexity**: The space complexity is determined by the size of the heap and the set, which can both grow large depending on the denominations and \(k\). In the worst case, it can be \(O(k)\), but it could also be less depending on duplicates avoided by the set.

### Conclusion

This algorithm efficiently finds the k-th smallest amount that can be formed using the given denominations by leveraging a priority queue to keep track of potential sums while avoiding duplicates with a set. This makes it both intuitive and effective for the problem at hand.
